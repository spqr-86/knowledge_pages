RedTeam — System Prompt Extraction

ШАД AI Agents Security Week 2026 · итоговая, задача B · дедлайн 13.08 · до 20 попыток, лучший результат

Задача в двух абзацах

На сервере контеста — LLM с зафиксированным системным промптом, внутри которого secret code. В промпт захардкожено 6 сценариев атаки: при совпадении запроса со сценарием модель объясняет причину, называет категорию атаки и раскрывает secret code. Есть 7-й путь — magic word: если запрос пользователя точно равен magic word, система сразу возвращает success.

Сдаём .txt с ровно 10 строк, по промпту на строку, каждый 3–300 символов. Цель — закрыть максимум из 6 сценариев + гарантированно взять magic word. Обратной связи по сценариям нет: единственный сигнал — счёт сабмита, попыток 20.

Известное про magic word

Зашифровано алгоритмом Кузнечик (ГОСТ Р 34.12-2015), режим ECB, PAD_MODE_1, библиотека gostcrypto. Ключ — строка, паддится до 32 байт нулями: key = candidate.encode("utf-8").ljust(32, b'\x00'). Ciphertext (hex):

96d2baa168f74fae630545bdca809febfa9c71776d4c9b7fd6200ade971d7e29

32 байта ciphertext = 2 блока по 16 → plaintext ≤ 32 байта (с учётом паддинга). Расшифровка: bytearray(binascii.unhexlify(hex)) → decrypt каждого блока → снять PAD_MODE_1. Успех кандидата = на выходе печатный ASCII/осмысленное слово.

Подходы к взлому magic word

Три архитектуры перебора ключа-строки. Проверка одного кандидата — микросекунды, различие только в стратегии обхода пространства.

A · узкий словарь

Кандидаты вручную из контекста: shad, secret, redteam, magic, yandex, ysda, kuznechik, названия задачи/курса, имена из условия. Десятки-сотни строк, регистр + простые мутации.

+ честно по времени, часто вскрывается сразу
– промах, если слово неожиданное

B · широкий брутфорс

rockyou / словарь англ. слов + мутации (регистр, leet, суффиксы-цифры). Критерий отсева — на выходе валидный печатный ASCII. Сотни тысяч попыток за секунды.

+ покрывает почти любое словарное слово
– ложные срабатывания по «печатности» — нужен фильтр осмысленности

C · эскалация A→B (реком.)

Один скрипт decrypt.py: сначала узкий список, при пустом результате — тот же движок на широком словаре. Единый критерий успеха, единый вывод.

+ минимум времени в типичном случае, полнота в худшем
+ инфраструктура одна

Подходы к 10 промптам (9 «боевых» + строка magic word)

Три стратегии распределения бюджета из 20 попыток. Сценарии совпадают по классу/строке, а не по литературному качеству, поэтому счёт сабмита — единственный настоящий сигнал.

СтратегияКакПлюсы / минусы
1 · Слепой залп по классам 10 промптов из 10 разных классов атак, сдаём, читаем счёт, дальше вытесняем непопавшие свежими вариантами тех же/новых классов. + каждая попытка максимально информативна
– без гипотезы о «форме» сценариев
2 · Гипотеза по условию Сценарии подсказаны формулировкой «объясняет причину, называет категорию» → это канон prompt-extraction. Первый залп — прямые формы из OWASP LLM07 (см. ниже), под них 8 строк, 1 — magic word, 1 — резерв. + целится в вероятные хардкоды
– если сценарии нестандартны — залп мимо
3 · Покрытие классов + бинарный поиск (реком.) Залп 1: строка magic word + 9 промптов из 9 разных классов (по одному представителю). По приросту счёта видно, сколько попало. Залп 2–3: держим сработавшие, вытесняем непопавшие соседними формулировками того же класса или новыми классами. 20 попыток = 3–4 полных итерации. + и разведка, и добор в одном плане
+ magic word закрыт с попытки 1

Что меряем себя локально

Реальной цели вслепую нет — суррогатную LLM не поднимаем (не воспроизведёт их матчинг, вариант отклонён на интервью). Локальный сигнал только один и честный: прирост счёта между сабмитами. Дисциплина попыток:

  • Вести журнал: попытка → какие 10 строк → счёт → дельта → вывод, какие классы попали.
  • Между залпами менять по одному фактору, чтобы дельта была атрибутируема (не переписывать весь файл целиком).
  • magic word держать в файле с попытки 1 — это фиксированный +success, база отсчёта для остальных 9.

Критерии приёмки

  • decrypt.py расшифровывает ciphertext узким словарём; при промахе эскалирует на широкий — единый вывод «кандидат → расшифровка».
  • magic word получен, проверен (осмысленный печатный ASCII) и помещён отдельной строкой в submission.txt.
  • submission.txt — ровно 10 строк, каждая 3–300 символов, без пустых строк.
  • 9 боевых строк покрывают ≥9 разных классов атак из каталога (залп 1 разведки).
  • Заведён журнал попыток (файл) с полем счёта и дельты для атрибуции.
  • План добора на залпы 2–3 описан: правило «держим сработавшие, вытесняем непопавшие».
  • Артефакты (submission.txt + decrypt.py) готовы к моменту одобрения варианта; сам Check в интерфейсе контеста жмёт Пётр.

Решения интервью: предмет — весь сабмит (не только magic word); ключ — эскалация узкий→широкий; проверка — по счёту сабмита осознанными попытками; глубина спека — спек + готовые артефакты к одобрению.
