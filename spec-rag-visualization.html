Spec: Визуализация архитектуры Regulatory-RAG

Дата: 2026-05-28 · Аудитория: лично Петр · Проект: ~/projects/ai/regulatory-rag · Repo: spqr-86/regulatory-rag

Задача

Regulatory-RAG — система с гибридным retrieval, FlashRank, LangGraph V7 пайплайном (12+ нод, conditional routing, триаж простой/сложный путь). Структура: src/infra, src/indexing, src/backends, src/v7/nodes/*, config, eval. Сложно держать в голове и ориентироваться.

Нужна статическая HTML-визуализация, деплоящаяся на GitHub Pages (ветка gh-pages репо spqr-86/regulatory-rag), которая:

  • Показывает поток данных по V7 graph (запрос → intent_gate → router → rag_simple → triage → … → generate_answer)
  • При клике на блок графа — проваливается в карту модулей/файлов этой стадии
  • Каждый файл и каждая ключевая функция/класс — кликабельная ссылка на GitHub (на строку, если возможно; иначе на файл)
  • Работает офлайн в браузере после деплоя, без бэкенда

Подходы (4 варианта)

Вариант A. Mermaid-граф + аккордеоны low effort

Один HTML-файл. Mermaid.js рисует flowchart V7 пайплайна (источник правды — парсинг src/v7/graph.py или ручной dict). Каждая нода кликабельна → раскрывается аккордеон под графом с описанием стадии и списком файлов/функций (каждая — ссылка на GitHub с #L42-L80). 

┌─────────────────────────────────────────────┐
│  [intent_gate] → [router] → [rag_simple]    │
│       ↓             ↓            ↓          │
│      END     [clarify_respond] [triage]     │
│                                  ↓          │
│                          ┌──────┴──────┐    │
│                       [verifier]  [complex]│
│                          ↓             ↓   │
│                  ...        [eval_complex] │
└─────────────────────────────────────────────┘
[Click node ↑] → разворачивается секция ↓

▸ rag_simple
  src/v7/nodes/rag_simple.py
    • rag_simple(state)            → GitHub#L23-L67
    • _hybrid_search(query, k)     → GitHub#L70-L98
  src/indexing/vector_store.py
    • VectorStore.search()         → GitHub#L15-L40
Минимум кода (~300 строк HTML). Mermaid из CDN. Парсинг graph.py регуляркой даёт честный source-of-truth.
Легко поддерживать: вся метадата в одном JSON-блоке внутри HTML.
"Провал" только на 1 уровень (граф → файлы). Без визуального drill-down в саму функцию.
Mermaid flowchart выглядит технически, не "красиво" из коробки.

Вариант B. D3.js zoomable canvas с уровнями high effort, max wow

Полноэкранный SVG-canvas на D3.js. Три уровня масштаба: (1) граф пайплайна с анимированным потоком запроса, (2) zoom на ноду → разворачиваются прямоугольники модулей/файлов, (3) zoom ещё глубже → функции с сигнатурами. Любой элемент — клик → GitHub. Поток данных подсвечивается при наведении. 

   LEVEL 1                    LEVEL 2 (zoom in)           LEVEL 3
   ┌──────┐                   ┌─ rag_simple ──────┐       ┌─ rag_simple.py ─┐
   │ pipe │  ← scroll/click → │  rag_simple.py    │  →    │ def rag_simple()│
   │ flow │                   │  vector_store.py  │       │ def _hybrid…()  │
   └──────┘                   │  chroma_helpers.py│       └─────────────────┘
                              └───────────────────┘
   ← pan, zoom, mini-map, breadcrumbs (Pipeline > rag_simple > rag_simple.py)
"Красиво проваливается" — именно как ты сформулировал. Очень нагляден поток данных.
Один canvas вмещает всю систему — можно увидеть и общее, и детали без переключения страниц.
~1000+ строк JS. Дольше делать, больше поверхность багов (зум/координаты).
Метаданные о функциях нужно собирать ast.parse-скриптом — пайплайн генерации усложняется.

Вариант C. Docusaurus / MkDocs-Material статика с интерактивными диаграммами medium effort

Полноценный сайт: главная — обзор архитектуры с Mermaid-диаграммой, отдельные страницы на каждый модуль (indexing, v7/nodes, infra) с автогенерацией списка файлов и функций из исходников. На каждую функцию — кнопка "Open in GitHub". Поиск, тёмная тема, навигация в сайдбаре. 

┌────────────┬────────────────────────────────────┐
│ Sidebar    │  # V7 Pipeline                     │
│            │                                    │
│ Overview   │  ```mermaid                        │
│ ▾ Pipeline │  intent_gate → router → rag_simple │
│   intent…  │  ```                               │
│   router   │                                    │
│   rag_simp │  ## Nodes                          │
│ ▸ Indexing │  - [intent_gate](./intent_gate)    │
│ ▸ Infra    │  - [router](./router) — routing…   │
│ ▸ Eval     │                                    │
└────────────┴────────────────────────────────────┘
Расширяется: можно добавлять заметки по решениям, ADR-ы, eval-результаты. Превращается в knowledge base.
Поиск, темы, мобилка из коробки.
Перебор для одного человека. Большой setup (Node.js билд, конфиги). Не "красивый граф", а скорее "красивая дока".
Drill-down не визуальный (клик-провал) а ссылочный (переход на страницу).

Вариант D. Excalidraw-style flowchart с боковой панелью кода medium effort, balanced

Split-screen: слева статический SVG-граф (нарисован вручную в стиле excalidraw или сгенерирован через elkjs/dagre), справа — панель деталей. Клик на ноду → справа появляется карточка стадии: описание, список файлов с раскрывающимися функциями, фрагменты кода (подгружаются с raw.githubusercontent.com или вшиты при билде), ссылки на GitHub. 

┌──────────────────────┬─────────────────────────────────┐
│   [intent_gate]      │  📦 rag_simple                  │
│        │             │  ─────────────────────          │
│   [router]──→[clari] │  Гибридный retrieval (BM25 +    │
│        │             │  semantic), FlashRank rerank.   │
│  ▸[rag_simple]◀───   │                                 │
│        │       │     │  📄 src/v7/nodes/rag_simple.py  │
│   [triage]     │     │    ▸ rag_simple(state) [L23]    │
│    │  │  │   [rewri] │    ▸ _hybrid_search()    [L70]  │
│  [vrf][cmplx]        │  📄 src/indexing/vector_store.py│
│                      │    ▸ VectorStore.search()       │
│                      │  ─────────────────────          │
│                      │  [Open in GitHub →]             │
└──────────────────────┴─────────────────────────────────┘
Баланс: визуально-красивый граф слева + структурированные детали справа. "Провал" происходит без потери общего обзора.
~500 строк HTML/JS. Без сложного зума. Layout через dagre — автоматически.
Можно показывать фрагменты исходного кода с подсветкой (highlight.js) прямо в панели.
Drill-down 1.5 уровня (граф → панель), не три как в D3-варианте.

Критерии приёмки

  • HTML-сайт деплоится на GitHub Pages из ветки gh-pages репо spqr-86/regulatory-rag и открывается по публичному URL
  • На главной видна вся структура V7 пайплайна (12 нод + рёбра, включая conditional routing)
  • Каждая нода V7 кликабельна и раскрывает список файлов модуля
  • Каждый файл в списке — ссылка на GitHub (github.com/spqr-86/regulatory-rag/blob/main/...)
  • Где есть отдельная значимая функция/класс — ссылка с якорем на строки (#L23-L67)
  • Покрыты не только V7, но и поддерживающие модули: src/infra, src/indexing, src/backends, config, eval
  • Источник правды для графа — src/v7/graph.py (либо парсится скриптом, либо явно синхронизируется при изменении)
  • Сборка одной командой: python scripts/build_docs.py или аналог; результат — папка docs-site/
  • CI на GitHub Actions автоматически билдит и публикует на gh-pages при пуше в main
  • Открывается локально без зависимостей (двойной клик по index.html работает)

Рекомендация

Для цели "понимать систему" и "красиво проваливается" с разумным effort — вариант D. Он даёт визуальный граф + структурированные детали + фрагменты кода справа, без сложности D3-зума и без overhead Docusaurus. Если хочется максимум wow — вариант B, но это +1-2 дня работы.
